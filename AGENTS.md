# AGENTS.md

## Project Overview
- This directory holds the Rocq mechanization of the Frost calculus from the
  paper *Haunting Bidirectional Typing* (`paper/frost.tex`, also rendered as
  `impredicative.pdf`). The Coq namespace is `src` (`-R . src` in
  `_CoqProject`).
- The paper presents a bidirectional type system for first-class polymorphism
  with mixed information flow, using **colours** (synthesised/inherited
  annotations on quantifiers), **modes** (TI, TC, FN M), **freezing**, and
  **skeletons** (partial types with ghosts).
- Authoritative paper sections:
  - `paper/sections/declarative.tex` — current declarative system (typing,
    subtyping/consistency, skeletons, skeleton inference).
  - `paper/sections/algorithmic.tex` — current algorithmic system.
  - Other section files (e.g. `declarative-old.tex`, `declarative-tags.tex`,
    `pattern.tex`) are **older drafts** and do *not* reflect the current
    formulation. Do not mechanize from them.
- Design document: [../docs/superpowers/specs/2026-05-09-frost-mechanization-design.md](../docs/superpowers/specs/2026-05-09-frost-mechanization-design.md).

## Phase Status

The mechanization is staged. Phases run sequentially.

| Phase | Scope | Status |
|---|---|---|
| 1 | All syntactic / judgment **definitions** for the declarative system; algorithmic placeholder. `make` succeeds, no proofs. | active |
| 2 | Declarative metatheory (subtyping soundness, general subsumption, refinement preserves wf, skeleton validity/safety, stability lemmas). | not started |
| 3 | Algorithmic system definitions and soundness/completeness vs. declarative. | not started |

## Encoding Conventions

These are load-bearing decisions — do not change without updating the design
doc.

- **Pure syntax in `language.ott`, rules in `def_extra.v`.** The ott file
  declares only grammars, substitutions, freevars, and formulas. All
  `Inductive` typing/subtyping/consistency/skeleton rules go in the
  appropriate `def_extra.v` (top-level for cross-system, `decl/` for
  declarative, `algo/` for algorithmic).
- **Single `typ` AST with colour-tagged binders.** `forall^c α. A` carries a
  `colour` (`S` for synthesised, `I` for inherited) on each binder. The
  paper's "synthesised type" / "inherited type" / "bidirectional type" are
  predicates on `typ`, not separate inductive types.
- **Tagged types (`unres_typ`, `tagged_typ`) and skeletons (`skel`,
  `unres_skel`, `tagged_skel`) are separate inductive sorts.** Skeletons
  extend types with `□` (Hole) and `*.P` (TopHole, the universal ghost).
- **Tag context `Δ`** is a finite set (`AtomSetImpl.t`). Disjoint union
  `Δ ⊎ Δ'` is encoded as `union Δ Δ'` plus a side-condition
  `inter Δ Δ' [=] empty`. Multiset switch is a deferred decision (see
  design doc §8).
- **Skeleton-scope context `Ψ`** is a `list typvar`, distinct from the
  term-context `Γ`. Used in skeleton well-formedness and refinement.
- **Locally-nameless via lngen**, including for ε tag variables. Cofinite
  quantification on binder rules. Use the existing `Metalib.Metatheory`
  imports.

## Build And Workflow

- Build everything: `make` from `mechanization/`.
- Regenerate ott/lngen output: `make ott && make lngen` (this runs
  automatically as part of `make`).
- Clean: `make clean`. Removes `*/def_ott.v`, `*/prop_ln.v`, `CoqMakefile`,
  `.FILE_LIST`.
- The Makefile already wires `language.ott → def_ott.v → prop_ln.v` and
  applies sed substitutions (e.g., `dE → Ψ`). Add new sed rules here if
  introducing more atom-set variable conventions.
- `_CoqProject` lists module roots; `coq_makefile` is regenerated from
  `tree -if` output, so just adding `.v` files in the right place is enough.

## Tooling

- **ott** for syntax declaration. Use `repr-locally-nameless` metavars and
  define substitutions/freevars per ott convention.
- **lngen** for locally-nameless infrastructure. Generates `prop_ln.v` with
  free-variable lemmas, opening, substitution lemmas, etc.
- **coqhammer** for proof automation in `ltac_utils.v`. Prefer `hammer` /
  `sauto` / `qauto` for goals after manual case splits; never leave hammer
  calls in committed proofs (resolve the term they suggest, or use a tactic
  combination that doesn't depend on the hammer being installed).
- The paper uses Unicode in math notation. ott files may use Unicode in
  rule formulae; the Makefile sed-rewrites a few atoms. Keep file encodings
  UTF-8 throughout.

## Style And Conventions

- Follow naming conventions from the reference repo
  [jiangsy/proof_worklist_remechnization](https://github.com/jiangsy/proof_worklist_remechnization),
  e.g. `d_typing`, `d_sub`, `d_wf_typ`, `d_chk_inf` for declarative-system
  inductives. Algorithmic counterparts get an `a_` prefix.
- Constructor names mirror paper rule labels: paper rule `\dtylab{Sub}`
  becomes `d_typing__sub`, etc.
- One `Inductive` per logical judgment; do not collapse multiple judgments
  into a single relation just to share constructors.
- Keep `def_extra.v` files focused on definitions and lemmas inseparable
  from the definitions (smart constructors, decidability instances). Pure
  metatheorems live in `prop_*.v`.
- Tactic style follows the reference repo — `eauto`-driven, with
  hammer-derived scripts simplified before commit.
- Comments document **why** an encoding is the way it is, not what the rule
  says (the paper says that). Cite paper rule names when a Coq constructor
  is non-obvious.
- Do not use `Axiom`. Track unfinished work with `Admitted` and the
  paper-citation comment that motivated leaving it open.

## Common Practices

- Read `paper/sections/declarative.tex` and `paper/sections/algorithmic.tex`
  directly when in doubt — these are the authoritative specs. The PDF is
  fine for human reading; LaTeX is fine for grep.
- Keep `mechanization/frost/language.ott` minimal. Resist the temptation
  to put rules into ott just because ott has `defns` syntax; we want the
  rules in Coq where they can be edited / debugged interactively.
- After editing `language.ott`, run `make` so `def_ott.v` and `prop_ln.v`
  regenerate. `_CoqProject` and `Makefile.coq` pick up new `.v` files
  automatically via the `tree`-based file list.
- Run `git status --short --branch` before and after significant edits.
- Do not edit `def_ott.v` or `prop_ln.v` by hand. If a generated file is
  missing a lemma, add the corresponding declaration in `language.ott` (or
  hand-write the lemma in `prop_basic.v`).

## Where Things Live (cheat sheet)

| Need to … | Edit … |
|---|---|
| Add a new syntactic constructor / sort | `frost/language.ott` |
| Add a meta-function shared by decl + algo | `frost/def_extra.v` |
| Add a predicate / well-formedness used by both | `frost/def_extra.v` |
| Add a declarative typing/subtyping rule | `frost/decl/def_extra.v` |
| Prove a declarative metatheorem | `frost/decl/prop_*.v` (pick the matching file) |
| Add an algorithmic rule | `frost/algo/def_extra.v` (Phase 3) |
| Add a global notation | `frost/notations.v` |
| Add a tactic | `frost/ltac_utils.v` |
